المخطط المعماري الشامل

1. شرح الطبقات (Layer-by-Layer Breakdown)

الطبقة الأولى: Client Layer (واجهات المستخدم)

الطبقة المرئية اللي بيتعامل معاها المستخدمين النهائيين. كل واجهة مخصصة لنوع مستخدم.

Customer App (Flutter)
  • iOS + Android من Codebase واحد
  • State Management: Riverpod
  • HTTP Client: Dio + Interceptors
  • Real-time: socket_io_client
  • Offline Cache: Hive
  • دعم RTL كامل + Dark Mode
Admin Dashboard (React)
  • Next.js 14 + TypeScript
  • TailwindCSS + shadcn/ui
  • React Query للـ Data Fetching
  • Recharts للرسوم البيانية
  • نظام RBAC للصلاحيات
  • 2FA إجباري
Provider Dashboard (React)
  • Web Responsive (يعمل على الجوال)
  • PWA Support للوصول السريع
  • إشعارات صوتية للطلبات الجديدة
  • Calendar للجدولة
  • تقارير مالية أسبوعية

الطبقة الثانية: Edge & Security Layer (الحماية والتوزيع)

طبقة الحماية الأولى — تستقبل كل الطلبات وتفلترها قبل وصولها للـ Backend.

Cloudflare CDN
  • توزيع المحتوى الجغرافي
  • DDoS Protection
  • WAF (Web App Firewall)
  • SSL/TLS Termination
  • Bot Mitigation
API Gateway (Nginx)
  • Reverse Proxy + Load Balancer
  • Rate Limiting (100 req/min/user)
  • Request Routing
  • Response Caching
  • API Versioning Support
Auth Service
  • JWT Token Generation
  • Refresh Token Rotation
  • RBAC Permission Check
  • OTP Validation
  • Session Management (Redis)

الطبقة الثالثة: Backend Services (الخدمات الخلفية)

القلب النابض للنظام. Modular Monolith في البداية باستخدام NestJS، قابلة للتحول لـ Microservices مستقلة عند الحاجة.

الخدمة المسؤولية Endpoints الرئيسية
User Service إدارة بيانات المستخدمين، العناوين، المفضلة /users, /addresses, /favorites
Company Service إدارة الشركات وتفاصيلها وخدماتها /companies, /companies/:id/services
Booking Service المحرك الرئيسي للحجوزات وإدارة دورة حياة الطلب /bookings, /bookings/:id/status
Payment Service التكامل مع بوابات الدفع وإدارة المحفظة /payments, /wallet, /refunds
Notification Service إرسال الإشعارات عبر القنوات المختلفة /notifications, /devices/register
Review Service التقييمات والمراجعات /reviews, /reviews/:id/reply
Catalog Service الفئات والخدمات والبحث /categories, /services, /search
Coupon Service الكوبونات والعروض /coupons/apply, /coupons/validate
Location Service الخرائط والمواقع وحساب المسافات /locations/nearby, /geocode
Tracking Service التتبع المباشر للفنيين (WebSocket) WSS /tracking/:orderId
Analytics Service التقارير والإحصائيات /analytics/dashboard, /reports
Admin Service كل عمليات لوحة الإدارة /admin/*

الطبقة الرابعة: Data Layer (طبقة البيانات)

تخزين البيانات بأنواعها المختلفة. كل نوع بيانات يُخزن في الـ Store المناسب لطبيعته.

التخزين الاستخدام ملاحظات
PostgreSQL 15+ البيانات الأساسية (Users, Orders, Companies, Payments) Master-Replica + Daily Backups
Redis Cache + Sessions + Rate Limiting + Pub/Sub Cluster Mode للـ HA
Elasticsearch البحث النصي + الـ Geo-spatial + الـ Logs 3 Nodes Cluster
S3 / Cloudflare R2 الصور والمستندات والفواتير Lifecycle Policy للأرشفة

2. تدفق طلب نموذجي (Sample Order Flow)

هذا مثال على كيفية تدفق طلب غسيل سيارات من الإنشاء حتى الإكمال:

📱 العميل يفتح التطبيق ويختار "غسيل سيارات"
↓
🌐 Request → Cloudflare → API Gateway → Auth Service (يتحقق من JWT)
↓
🔍 Catalog Service يرجع قائمة الشركات + Location Service يحسب المسافة
↓
📝 العميل يختار شركة ويحجز → Booking Service ينشئ الطلب (Status: Pending)
↓
💳 Payment Service يحجز المبلغ من البطاقة (Pre-authorization)
↓
🔔 Notification Service → Push Notification للشركة عبر FCM
↓
🏢 Provider Dashboard يستلم الطلب → الشركة تقبل (خلال 5 دقائق)
↓
🚗 الفني يبدأ التوجه → Tracking Service يبث الموقع عبر WebSocket
↓
📲 العميل يرى الموقع المباشر + ETA على الخريطة
↓
✅ الفني يكمل الخدمة → Status: Completed
↓
💰 Payment Service يقبض المبلغ + يحسب العمولة + يضيف للتسوية الأسبوعية
↓
⭐ Review Service يدعو العميل للتقييم

3. اعتبارات قابلية التوسع (Scalability)

المرحلة 1: 0-10K MAU
  • Single EC2 Instance + RDS Small
  • Modular Monolith
  • Single Region (الدوحة)
  • التكلفة الشهرية ~$800
المرحلة 2: 10K-50K MAU
  • Auto-scaling Group + Load Balancer
  • RDS Read Replicas
  • Redis Cluster Mode
  • CDN Caching Strategy
المرحلة 3: 50K+ MAU
  • Split into Microservices
  • Kubernetes (EKS)
  • Multi-region Deployment
  • Database Sharding

4. توصيات أمنية حرجة

  • 📌 تشفير كل الـ Endpoints بـ HTTPS / TLS 1.3
  • 📌 تخزين كلمات السر بـ Bcrypt (cost factor 12+)
  • 📌 OTP صالحة لـ 5 دقائق فقط ومرة واحدة
  • 📌 JWT Access Token صلاحية 15 دقيقة + Refresh Token 30 يوم
  • 📌 لا تخزن بيانات البطاقات أبداً — كلها تمر عبر Payment Gateway
  • 📌 Rate Limiting صارم: 5 OTP/ساعة لكل رقم، 100 req/min للـ API
  • 📌 Audit Logs لكل عمليات لوحة الإدارة الحساسة
  • 📌 PCI-DSS Compliance للمدفوعات
  • 📌 GDPR / قانون حماية البيانات القطري للخصوصية
  • 📌 Penetration Testing سنوي من جهة خارجية
